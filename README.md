### 1. Переповнення байта (Byte overflow)

set 0 255 
inc 0 
get 0
`get 0` покаже `0` замість `256`, оскільки `uint8_t` переповнюється і загортається

### 2. Числа з рухомою комою (`0.1 + 0.2 != 0.3`)
Код scratch.cpp:

#include <iostream>
int main() { 
    std::cout << std::boolalpha << (0.1 + 0.2 == 0.3) << '\n'; 
    return 0; 
}

Вивід:
false

Числа з рухомою комою зберігаються у форматі IEEE-754\. Більшість десяткових дробів (зокрема 0.1 та 0.2) не мають точного представлення у двійковій мантисі, через що при додаванні виникає незначна похибка округлення. Порівняння через `==` повертає `false`.

### 3. Представлення C-рядка "AB\0"` у пам'яті

ember> set 0 65
ember> set 1 66
ember> set 2 00
ember> dump
0000  41 42 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |AB..............|

* Байтам зі значеннями `65` та `66` відповідають ASCII-символи `'A'` та `'B'`. Байт `0` виконує роль нуль-термінатора `'\0'`, що позначає кінець C-рядка. У текстовій колонці дампу нуль відображається як замінник `.`.

### 4. Вплив ініціалізації пам'яті (прибирання `{}`)
```  
// Початковий код (занулення):  
// Byte data[MEM_SIZE]{};  
// Код для досліду (неініціалізований масив):  
Byte data[MEM_SIZE];  
```

«Після вилучення* *{}* *дамп пам'яті все одно показує нулі. Це пояснюється тим, що операційна система видає процесу нові занулені сторінки пам'яті (або об'єкт має static-ініціалізацію). Проте формально ця пам'ять є неініціалізованою, і покладатися на ці нулі не можна, оскільки це невизначена поведінка (UB).»*
